## 1. 验收范围与约束

- 只验收 Web 端效能度量页面正文，应用导航菜单不在本轮范围内。
- 正式环境源页面：`https://zgsm.sangfor.com/kanban/`
- 迁移页面示例：`http://localhost:3001/my-workspace/metrics`
- 文档中的 `{workspaceSlug}` 替换为实际工作区标识，例如 `my-workspace`。
- 源页面与迁移页面应选择相同日期范围、组织、人员、项目或仓库后再比较。
- 正式环境以只读验证为主。新增、编辑、删除、重试、取消、手工调整等写操作，只检查入口、弹窗和校验，不点击最终确认。

- “质量”“覆盖”不属于本次迁移验收范围；“需求”对应 `/metrics/needs`。

## 9. 推荐点击顺序

按以下顺序验收可以减少重复选择日期和对象：

1. 总览：需求排行 → 需求详情 → 仓库 → 提交 → 任务 → 工作目录 → 人员。
2. 用量：部门树 → 成员页签 → 成员弹窗 → 人员完整详情。
3. 效率：依次检查组织、人员、项目、仓库四种对象及返回汇总。
4. 成本：部门对比 → 子部门汇总 → 成员 → 人员详情。
5. 贡献：依次检查组织、人员、项目、仓库四种聚焦视图及内部链接。
6. 需求、任务、提交列表：分别进入详情，并验证交叉链接和返回状态。
7. 设置：依次检查八个页签，再检查明细查询的请求、日志和 Trace 下钻。
8. 最后检查写操作弹窗，全部在最终确认前取消。

发现问题时，至少记录入口页面、当前筛选、点击对象、期望结果和实际结果。涉及接口问题时补充请求 URL、状态码和响应摘要，不记录账号、Cookie 或令牌。

|---|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  | 待处理 |

优先级建议：

- `P0`：页面不可进入、核心数据链路中断或正式环境存在破坏性风险。
- `P1`：主要下钻链路不可用、目标对象错误或关键内容缺失。
- `P2`：返回状态丢失、次要交互异常或局部内容差异。
- `P3`：样式、文案、间距等不影响使用的问题。

## 11. 完成标准

- 核心看板、列表页、详情页和设置页的适用项均完成点击验收。
- 所有可点击项都能进入正确对象或呈现正确的当前页状态。
- 详情页交叉链接不存在 404、对象串联错误或无法返回的问题。
- 写操作没有在正式环境提交，弹窗和基础校验已完成只读检查。
- `P0`、`P1` 缺陷全部关闭；`P2`、`P3` 已记录并明确后续处理结论。
- 最终浏览器端到端对比仍按迁移执行计划作为统一收口待办执行。
