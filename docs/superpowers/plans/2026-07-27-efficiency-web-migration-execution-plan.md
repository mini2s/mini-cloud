# 效能度量 Web 功能迁移执行计划

**日期**：2026-07-27
**源项目**：`../efficiency-dashboard`
**目标项目**：`mini-cloud`
**目标范围**：仅 Web
**计划状态**：迁移遗漏代码修复完成，等待统一浏览器终验

## 1. 实施范围

本次迁移仅处理 `apps/web` 中的“效能度量”模块，并复用
`efficiency-dashboard` 现有后端、数据库和数据采集能力。

共享的数据逻辑和页面组件仍按目标项目架构分别放在：

- `packages/core/efficiency/`
- `packages/views/efficiency/`

本次不包含：

- Desktop 路由与桌面端适配
- `apps/admin` 页面迁移
- 后端、数据库及采集计算链路迁移
- 构建、部署和发布
- 新增单元测试、集成测试和 Playwright E2E

自动化测试用例在功能迁移完成后单独安排。

## 2. 执行原则

1. 按阶段实施并保留可独立检查的代码边界。
2. 全部已识别问题修复完成后，再统一执行浏览器终验。
3. 每个阶段保持可独立提交、可暂停、可继续。
4. 优先保证真实数据链路和核心流程闭环。
5. 使用 AI 并行处理数据层与页面层，由一名负责人统一集成。
6. 不覆盖或回退工作区中与本任务无关的已有修改。
7. 后续迁移批次暂不执行浏览器对比验收，由用户人工校验页面结果。
8. 整体功能迁移完成后，统一补做正式环境与迁移页面的浏览器端到端对比，
   并将结果纳入最终交付验收。

## 4. 分阶段验收

### 阶段1：真实数据链路

实施完成后立即验收：

- Web 可以通过同源代理访问现有效能后端。
- 普通接口和 chat 接口响应可以正确解包。
- 至少一个总览样板接口返回真实数据。
- 关闭 Mock 后页面不会进入 `NOT_WIRED`。

验收通过后进入阶段2。

### 阶段2：核心看板

实施完成后立即验收：

- 总览、使用、效率、成本和贡献页面可以访问。
- 页面使用真实后端数据。
- 时间范围、部门或主体切换能够触发正确查询。
- 从原看板抽样核对关键指标，口径一致。

验收通过后进入阶段3。

### 阶段3：详情与写操作

实施完成后立即验收：

- 用户、仓库、项目、需求、任务和提交详情可访问。
- 看板到详情的下钻与返回路径正常。
- 必要新增、修改和删除操作调用真实接口。
- 写操作完成后刷新页面，结果仍然存在。

验收通过后进入阶段4。

### 阶段4：功能补齐

实施完成后立即验收：

- 设置和平台运维页面接入真实数据。
- 主要遗漏页面、入口和交互已经补齐。
- 用户能够访问的路径不存在接口占位。
- 无明显白屏、死循环或阻断性错误。

验收通过后进入最终交付。

## 5. 风险项与风险时间

7月31日预留为共享风险缓冲。以下风险时间不逐项累加，优先从该缓冲中消耗。

| 风险项 | 预留时间 | 处理方式 |
|---|---:|---|
| 后端地址、代理、CORS或鉴权不符合预期 | 0.5天 | 优先保证样板接口闭环，再继续批量接入 |
| 普通接口与chat信封、字段类型存在差异 | 0.5天 | 在数据适配层集中处理，不在页面分别兼容 |
| `chat-stats`或`dept-sync`不可用 | 0.5天 | 明确降级范围并记录外部阻塞 |
| 指标比例、日期范围或聚合口径不一致 | 0.5天 | 与原看板抽样对账后统一修正 |
| 写接口权限不足或刷新后未持久化 | 0.5天 | 暂停后续迁移，优先完成读写闭环 |
| 临时插入其他事项 | 0.5～1天 | 在最近的阶段验收点暂停，按剩余净工时继续 |

如果同时出现多个高风险问题，记录为外部阻塞并顺延对应阶段，不通过压缩验收时间补偿。
