# Workflow 编辑器配置面板布局设计

## 背景

当前 Workflow 编辑器节点配置面板将基础信息、执行者、审核者、类型专属规则、连接信息和操作区纵向堆叠。区域标题、说明文字、状态徽标和嵌套配置同时出现，配置项之间的区分主要依赖线框和颜色，导致视觉层级混乱；即使是普通节点，用户也需要滚动才能完成常用配置。

本次调整以减少滚动和提高配置项辨识度为核心，不改变节点配置的数据模型、保存机制或业务能力。

## 目标

- 使用双列布局提高横向空间利用率，让普通节点的主要配置尽量在一屏内完成。
- 通过留白、对齐、字号和稳定的字段结构区分区域，减少颜色、边框和嵌套卡片。
- 缩短并就地放置必要提示，移除重复解释。
- 让删除、保存和试运行始终可见，同时通过按钮层级降低删除操作的视觉权重。
- 保持普通节点、拆分节点、网关和注释节点的配置能力不变。

## 非目标

- 不改变 Workflow 节点、阶段、角色或拆分规则的数据结构。
- 不改变 Zustand 草稿、React Query、保存、阶段创建、删除或试运行数据流。
- 不重做画布、节点卡片、边或自动布局。
- 不为配置面板引入标签页、折叠状态或新的全局状态。
- 不改变运行详情面板的信息结构。

## 信息架构

编辑面板在桌面端使用约 800px 的双列主体：

```text
节点名称                                      关闭
所属阶段 · 最近运行状态

基础信息                         执行配置
名称                             执行者与分配方式
阶段                             审核者与审核方式
描述

节点规则                         连接概览
仅按节点类型展示                 仅在有意义时展示

删除节点                         试运行  保存
```

左列承载节点自身属性和类型专属规则，右列承载参与者配置和连接概览。字段较少的网关、注释节点只渲染适用区域，不保留空白占位。拆分节点增加拆分规则，但不重复展示执行者或审核者说明。

## 视觉设计

配置区不使用逐层嵌套的卡片。区域边界主要由以下方式建立：

- 使用一致的列起点、字段间距和区域间距形成分组。
- 区域标题采用紧凑的中等字重，字段标签使用较低层级字号。
- 仅保留一条弱化的列间分隔线，以及固定底部操作栏的顶部分隔线。
- 默认状态不使用彩色背景；缺失或可选状态以短文字和图标表达。
- 仅校验错误和破坏性操作使用语义强调色。
- 执行者与审核者使用同构布局，使分配模式、选择器和状态位置保持一致。

面板头部只保留节点名称、所属阶段和最近运行状态。阶段与运行状态作为紧凑元信息展示，避免多个同权重徽标占据头部空间。

## 提示与文案

- 删除区域标题下方重复说明，不使用说明文字解释界面结构。
- 仅在容易误解或存在业务约束的字段下保留一行短提示。
- 字段提示跟随对应控件，不集中堆在区域标题中。
- 中英文文案保持相同的信息层级和含义。
- API 地址、拆分并发数和失败容忍数等约束继续提供必要说明或错误反馈。

## 交互设计

- 面板头部和底部操作栏固定，中间配置主体独立滚动。
- 保存按钮始终可见；只有存在本地草稿时可用，行为保持不变。
- 拆分节点的试运行按钮位于底部操作栏，与保存并列。
- 删除节点按钮固定在底部操作栏左侧，使用低权重按钮样式和破坏性文字色；继续使用现有删除调用链。
- 阶段新建表单继续就地展开，但限制在基础信息区域内。
- 分配模式继续支持直接分配、角色和 API，不增加新的切换步骤。

## 响应式与溢出

- 视口宽度不小于 1280px 时，面板使用 800px 双列布局；面板宽度始终不超过视口减去 32px。
- 视口宽度小于 1280px 时自动退化为单列，保持相同的信息顺序，不引入标签页或折叠交互。
- 长节点名、阶段名、角色名和参与者名称必须截断或换行，不得撑开面板。
- 中间主体可以滚动，但头部和底部操作始终保持可见。
- 在不小于 1280 x 768 的桌面视口下，普通节点的基础信息和参与者配置应无需滚动完成；拆分节点允许因专属规则产生少量滚动。

## 组件边界

扩展 `WorkflowNodeDetailPanelShell`，增加可选的固定底部操作区和响应式宽度能力。默认行为保持不变，避免影响运行详情面板。

`NodeConfigPanel` 的展示层按职责拆分为局部组件：

- 基础信息区域：名称、阶段、描述和阶段新建。
- 参与者配置区域：统一承载执行者与审核者的模式和选择控件。
- 类型专属区域：注释绑定、网关语义或拆分规则。
- 连接概览区域：展示适用节点的上下游数量。
- 底部操作区：删除节点、试运行和保存。

这些组件只接收现有值和事件回调，不拥有新的业务状态。节点草稿仍由 `useWorkflowEditorStore` 管理，服务端数据仍由现有 React Query hooks 获取。

## 错误与状态反馈

- 保存、删除和阶段创建失败继续使用现有 toast 或就地错误信息。
- 配置缺失状态靠近对应区域标题或字段展示，不为正常状态增加大面积颜色。
- 禁用状态保持控件不可操作，并维持足够的文字对比度。
- 网关类型无效、API 地址不完整等错误继续使用语义错误色，不依赖颜色作为唯一信息载体。

## 测试与验证

- 更新 `WorkflowNodeDetailPanelShell` 测试，覆盖可选底部操作区和默认行为不变。
- 更新 `NodeConfigPanel` 测试，覆盖双列区域结构、稳定的信息顺序和底部操作。
- 保留并适配执行者、审核者、角色、API、保存、阶段创建和删除相关测试。
- 覆盖普通、拆分、网关和注释节点的条件区域，确认无空白占位或重复配置。
- 运行 `packages/views` 中配置面板和共享外壳的相关 Vitest 测试，不执行全量测试。
- 使用桌面宽窗口和窄窗口截图检查区域区分、滚动范围、固定操作栏、文字溢出和画布剩余空间。

## 验收标准

- 普通节点在不小于 1280 x 768 的桌面视口下，无需滚动即可完成基础信息、执行者和审核者配置。
- 配置区域主要通过空间、对齐和字体层级区分，没有嵌套卡片或大面积状态底色。
- 执行者与审核者使用一致的布局和交互结构。
- 面板仅中间主体滚动，保存与试运行始终可见。
- 删除节点始终可见，但不与保存操作同权展示。
- 窄窗口可用且无横向溢出。
- 所有现有节点类型、配置模式和数据流保持不变。
