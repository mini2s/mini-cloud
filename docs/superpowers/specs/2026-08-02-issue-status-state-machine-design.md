# Issue 状态机规则

我理解这次规则应该这样落地：

1. 新建任务
- 没有“分配”执行对象：状态自动放到 `backlog`（待规划）。
- 已有“分配”执行对象：状态自动放到 `todo`（待办）。
- 这里的“分配”我按 `assignee_type / assignee_id` 理解，不是“负责人”字段。

2. 待规划
- 待规划只能放“未分配”的任务。
- 用户从待规划拖到其他列时，如果还没分配，前端直接拦住并提示“请先分配任务”。
- 如果其他状态拖回待规划，后端也会清空 `assignee_type / assignee_id`，并停止当前执行。

3. 待办
- 待办是“已分配但还没开始干活”的状态。
- 待办可以拖到进行中、完成、阻塞等其他状态。
- 其他状态拖回待办时，保留分配，但要结束当前执行：取消任务队列、取消 workflow run，并把相关 workflow node run 一并结束/取消。

4. 真正开始执行
- 只有进入 `in_progress` 才启动数智人 / Workflow。
- `backlog` 和 `todo` 都不启动。

我建议按这个方案改，核心约束放后端兜底，前端做交互提示。这样即使有人绕过 UI 调 API，也不会把未分配任务错误挪出待规划。

确认这版理解没问题我就开改。
