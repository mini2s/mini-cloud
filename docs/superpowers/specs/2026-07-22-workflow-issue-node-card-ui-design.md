# 工作流与 Issue 全景图节点卡片 UI 统一设计

## 背景

工作流编辑器节点已经通过 `WorkflowCanvasNodeShell` 形成稳定的卡片表面、交互反馈与 React Flow 端口样式；Issue 全景图节点仍独立实现相似能力，导致圆角、阴影、悬浮、选中和端口视觉不一致。

本次改动统一两类节点卡片的 UI 外壳，同时保留各自的业务内容、状态计算和画布交互。

## 目标

- 工作流编辑器与 Issue 全景图直接复用同一个节点卡片外壳组件。
- 统一卡片表面、圆角、描边、阴影、悬浮、焦点、选中态和连接端口。
- 保留两类节点现有尺寸、信息结构、事件和业务状态。
- 保留 Issue 全景图进入时对 blocked、待处理状态最高优先级节点的现有聚焦逻辑及其视觉反馈，不修改候选选择或排序算法。

## 非目标

- 不统一工作流节点与 Issue 节点的业务内容布局。
- 不改变 React Flow 布局算法、节点位置或边样式。
- 不改变 Issue 全景图初始聚焦、搜索、筛选、关系追踪和点击行为。
- 不改变工作流节点的形状、Worker/Critic、拆分节点或新增连接节点逻辑。

## 组件设计

将 `WorkflowCanvasNodeShell` 从工作流目录提升为 `packages/views/common/canvas-node-shell.tsx` 中的 `CanvasNodeShell`。工作流节点和 Issue 节点直接复用该中性组件，避免 `issues` 反向依赖 `workflows`。

共享外壳负责：

- 稳定的宽高与内容容器。
- 卡片表面、圆角、描边、阴影及浅色层次。
- 悬浮、键盘焦点和选中反馈。
- React Flow 左右及底部端口。
- 通过 `className`、`surfaceClassName`、`contentClassName` 和端口配置开放有限的视觉扩展。

领域组件负责：

- 工作流节点继续计算节点形状、角色配置、节点类型和新增连接行为。
- Issue 节点继续计算状态、优先级、父子进度、负责人、关系高亮及初始聚焦状态。
- Issue 的 selected、ancestor、descendant、initial highlight、muted 和 unrelated 状态通过共享外壳的扩展属性映射到表面样式，不进入共享组件的业务判断。

## 视觉规则

- 以工作流编辑器节点卡片为基准，使用一致的细描边、浅色层次、轻阴影和悬浮上移反馈。
- 统一使用紧凑圆角，避免 Issue 节点现有的过大圆角。
- Issue 节点保留左侧状态线，关系和初始聚焦颜色仍由 Issue 业务状态决定。
- Issue 关系色只强化描边、状态线和轻量光晕，避免大面积背景色破坏统一表面。
- Issue 标题、编号、状态、优先级、子任务进度和负责人保持现有信息层级与尺寸。
- 连接端口统一由共享外壳渲染，但工作流的“新增连接节点”端口行为仅在工作流侧启用。

## 交互与可访问性

- 保留现有鼠标悬浮、节点选择、双击、搜索聚焦和打开详情行为。
- 共享外壳保持可见的键盘焦点环与正确的按钮/可交互语义。
- Issue 初始聚焦节点在共享表面上仍具有清晰、可辨识的强调状态，其他节点的弱化状态保持不变。

## 测试

- 更新共享外壳测试，覆盖表面、选中态和端口配置。
- 更新工作流节点测试，确认迁移后角色、节点类型和新增连接行为不变。
- 为 Issue 节点补充或更新测试，确认业务信息、关系状态和初始聚焦样式仍正确传递。
- 运行 `@multica/views` 中与共享外壳、工作流节点和 Issue 全景图相关的 Vitest 测试，不执行全量测试。
- 通过桌面与移动尺寸截图检查两处画布，确认卡片一致、内容无溢出且节点状态可辨识。

## 验收标准

- 两处节点卡片由同一个共享外壳组件渲染。
- 两处卡片在圆角、表面、阴影、悬浮、焦点和端口上视觉一致。
- 两处业务内容与交互无回归。
- Issue 全景图现有的 blocked、待处理状态最高优先级节点初始聚焦逻辑和 UI 状态完整保留。
