# Issue 全景图详情面板布局设计

## 目标

将 Workflow 配置面板的低装饰分区、宽面板和固定操作栏复用到 Issue 全景图，同时针对普通运行节点与 Split 父节点采用不同的信息密度策略。

## 普通运行节点

- 面板宽度为 800px，视口小于 1280px 时退化为单列。
- 左列展示状态与下一步、输出证据；右列展示子 Issue 上下文、执行者与审核者、运行事实。
- 打开会话、查看 Issue、解阻和重试移动到共享外壳固定底栏。
- 状态诊断不再使用嵌套卡片，主要通过留白、标题和字段对齐分组。
- 仅错误、阻塞和恢复操作使用语义色。

## Split 父节点

- Issue 全景图中的 Split 父节点继续使用 `SplitReviewPanel`，但面板宽度同步为 800px。
- 结论摘要与依赖/释放规则组成双列概览。
- 子 Issue 草稿台账和 Agent 调整对话保持全宽，避免复杂编辑控件被压缩。
- 取消、确认创建等操作使用共享外壳固定底栏，替代滚动区内的 sticky 操作栏。
- 保留 Split 生成、恢复、重置、编辑草稿、审核和取消的数据流。

## 响应式与验证

- 1280px 及以上视口使用双列概览；更窄视口使用单列。
- 仅中间正文滚动，头部和操作栏固定。
- 覆盖普通节点、Split 父节点和 Split 子 Issue 三类详情。
- 运行两个详情面板及 Issue 全景图相关 Vitest，并执行 `@multica/views` 类型检查。
