# Workflow Split 节点 UI 统一设计

## 背景

Workflow 编辑器中的普通节点已经形成一致的卡片结构：统一画布外壳、标题与类型徽标、可选描述，以及底部带分隔线的双栏元数据区。Split 节点虽然复用了相同外壳，内部仍由 `SplitNodeCard` 渲染分支图标和彩色标签，视觉层级和信息密度与其他节点不同。

## 目标

- Split 节点与其他编辑器节点采用一致的内容结构和视觉语言。
- 保留 split 模式、并发数、最大失败数和子 workflow 等必要信息。
- 保持节点尺寸、选择、打开、连线和新增连接节点行为不变。
- 不影响 workflow 运行页面中的 split 节点卡片。

## 非目标

- 不修改 split 配置或运行逻辑。
- 不调整画布布局、节点位置、端口或边样式。
- 不重构通用节点外壳或运行态 `SplitNodeCard`。
- 不改变普通节点、Gateway 节点和 Annotation 节点。

## 实现边界

在 `CompactWorkerNode` 的 split 分支中渲染编辑器专用内容，不再为该分支使用 `SplitNodeCard`。`SplitNodeCard` 继续服务自身的运行态和进度语义，不新增 editor 变体。

这样可以让 split 编辑器节点直接遵循相邻普通节点的内容结构，同时避免把编辑器视觉职责放入运行态组件。

## 视觉结构

Split 节点继续使用 `WorkflowCanvasNodeShell`，尺寸保持 `296 x 152`。

顶部信息区与普通节点一致：

- 左侧显示节点标题，最多两行。
- 标题下方显示可选描述，最多两行。
- 右侧显示紧凑的 `Split` 类型徽标，样式与 `Agent`、`Logic`、`Note` 徽标一致。
- Rectangle 形状不增加额外图标；其他显式形状仍使用现有形状标记。

底部元数据区使用与普通节点一致的顶部分隔线和双栏布局：

- 左栏为“子 workflow”，显示 workflow 名称；未选择时显示低强调的缺失状态。
- 右栏为“执行策略”，主值显示 `barrier` 或 `pipeline`，辅助信息显示并发数；仅 `barrier` 模式显示最大失败数。
- 元数据使用普通节点相同的标签字号、正文层级和状态圆点，不再使用蓝色模式胶囊或多枚灰色标签。

所有新增可见文案使用 workflows 命名空间的中英文翻译，不引入硬编码的新增 UI 文案。

## 交互与可访问性

- 保留节点双击打开、Enter/Space 打开、选中反馈和 title 提示。
- 保留左右及底部 React Flow 端口，以及右侧新增连接节点操作。
- 类型徽标和元数据不新增独立交互，不制造嵌套按钮。
- 长标题、描述、workflow 名称和策略信息使用行数限制与自然换行，不能撑大节点。

## 测试与验证

- 更新 `compact-worker-node.test.tsx` 中的 split 节点断言，验证标题、类型徽标、双栏元数据和配置值。
- 验证 split 节点不再渲染旧的彩色标签结构。
- 保留节点尺寸、共享外壳、端口及打开行为的既有测试。
- 运行 `@multica/views` 中 compact worker node 的相关 Vitest 测试，不执行全量测试。
- 启动现有前端并通过截图检查普通节点与 split 节点在同一画布中的视觉一致性、文本溢出和交互状态。

## 验收标准

- Split 节点具有与普通节点一致的标题、描述、类型徽标和底部双栏元数据结构。
- Split 配置和子 workflow 信息仍可在卡片中快速扫描。
- 卡片内不再出现旧分支图标、蓝色模式胶囊和灰色参数标签组。
- 运行态 `SplitNodeCard` 的结构和行为不受影响。
- 相关模块测试通过，截图中内容无溢出或重叠。
