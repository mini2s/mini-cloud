# Issue 全景图 Split 节点运行态 UI 设计

## 目标

Issue 全景图中的 split 节点复用 workflow 编辑器已经确认的标题与类型徽标结构，同时优先展示运行状态和子 issue 进度。覆盖审核中、进行中和已完成状态，不改变子 issue 展开、节点选择或画布布局。

## 结构

- 顶部与普通运行卡一致，左侧显示节点标题，右侧显示主要运行状态，不再显示分支图标。
- 中部显示共享 `Split` 类型徽标；`barrier` / `pipeline` 使用低强调辅助文字保留。
- 底部保留子 issue 数量、进度摘要和展开/收起操作。
- 没有子 issue 进度时继续展示拆分规划者与审核者，避免生成阶段丢失执行上下文。
- 三种目标运行状态使用同一 DOM 结构，仅状态图标、状态文字和进度内容变化。

## 复用边界

新增中性的 `WorkflowNodeTypeBadge`，供编辑器节点和 Issue 全景图 split 节点共同使用。运行状态、模式和子 issue 进度仍由 `RuntimeNodeCard` 负责，不将运行态业务放入共享组件。

## 验证

- 编辑器节点测试验证共享徽标迁移后结构不变。
- Issue 运行节点测试分别覆盖审核中、进行中、已完成，以及模式弱化和子 issue 展开行为。
- 运行两个相关 Vitest 文件和 `@multica/views` TypeScript 检查。
- 通过实际页面截图检查普通节点、编辑器 split 节点和 Issue 运行态 split 节点的视觉一致性。
