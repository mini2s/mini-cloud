# Workflow 始末节点设计

## 背景与目标

Workflow 编辑器需要支持显式的开始节点和结束节点，用于表达流程边界。两个节点由用户手动添加、编辑和连线，并持久化到现有 workflow 定义中。

首期始末节点不执行任务、不产生运行记录，也不改变真实任务的调度结果。数据模型和运行入口需要保留清晰的类型分支，以便后续增加开始或结束处理逻辑。

## 范围

本期包含：

- 每个 workflow 可选地添加最多一个开始节点和一个结束节点。
- 始末节点支持编辑标题、描述、所属阶段和画布位置。
- 用户手动创建始末节点与真实节点之间的边。
- Workflow 编辑器、模板预览和运行详情均展示始末节点。
- 后端校验节点唯一性和边方向。
- 运行引擎忽略始末节点的执行，并按真实节点之间的边调度。

本期不包含：

- 自动创建或自动连接始末节点。
- 为始末节点配置 worker、critic、role 或其他执行参数。
- 始末节点的 node run、输出、状态事件或业务处理逻辑。
- 将普通节点转换为始末节点，或在开始与结束类型之间切换。

## 数据模型

始末节点沿用现有 `workflow_node` 表，通过 `format_schema.type` 标识：

```text
start
end
```

节点沿用现有的 `title`、`description`、`stage_id`、`position_x` 和 `position_y` 字段。worker、critic 和 role 相关字段保持为空。连接关系继续使用现有 `workflow_edge` 表。

共享 TypeScript 节点格式解析增加 `start` 和 `end` 两种 `WorkflowNodeFormatKind`，并提供统一的 `isBoundaryNode`、`isStartNode` 和 `isEndNode` 判定。Go 服务端提供对应的格式解析和判定，运行与校验代码不直接散落 JSON 字符串判断。

数据库增加基于 workflow ID 和 `format_schema.type` 的部分唯一索引，分别约束每个 workflow 最多一个 start 和一个 end。服务端在写入前执行相同的领域校验，以返回明确错误；数据库索引负责并发情况下的最终一致性。

模板克隆继续复制现有节点和边，因此始末节点会随模板一起克隆。节点删除继续复用现有边级联清理。

## 编辑器交互

主节点模板选择器增加“开始”和“结束”两项。已存在同类型节点时，对应添加项禁用，并说明每个 workflow 只能存在一个该类型节点。连接节点旁的快捷添加选择器不提供始末节点，避免创建时隐式生成不符合方向约束的边。

通过拖放创建时，节点归属拖放位置对应的阶段。通过主选择器点击创建时，节点使用当前默认放置规则，用户可随后在受限编辑面板中修改所属阶段。

始末节点使用独立、紧凑的边界节点组件：

- 开始节点显示播放图标、标题和右侧 source handle。
- 结束节点显示终止图标、标题和左侧 target handle。
- 两者使用固定尺寸和现有设计 token，与任务卡保持一致但有明确视觉区分。
- 两者可选中、拖动、删除和打开编辑面板。
- 两者不显示执行者、审核者、执行配置或“添加下游节点”快捷按钮。

编辑面板复用现有面板外壳，只展示标题、描述和所属阶段。画布拖动维护位置。节点类型创建后不可编辑。

模板预览和运行详情使用相同边界节点视觉，并保持只读。

## 连线规则

用户手动创建和删除始末节点的边。允许一个开始节点连接多个执行节点，也允许多个执行节点汇入一个结束节点。这里的执行节点不包含 annotation、start 或 end。

以下连接非法：

- 任意节点连接到开始节点。
- 结束节点连接到任意节点。
- 开始节点直接连接结束节点。
- 始末节点连接 annotation 节点。

前端通过可用 handle 和连接校验即时阻止非法操作。服务端创建边接口执行权威校验，避免 API 调用绕过前端。现有重复边和 DAG 循环规则继续适用。

## 运行语义

首期始末节点采用“拓扑穿透、不创建 node run”的无副作用语义。

启动 workflow run 时，服务端仍读取完整节点和边，但构建执行图时：

1. 过滤 start 和 end 节点，不为其创建 `workflow_node_run`。
2. 过滤任一端为 start 或 end 的边。
3. 只使用真实节点之间的边计算根节点和上游依赖。
4. 只使用真实 node run 判断 workflow run 是否完成或失败。

因此 `start -> task` 目前不会主动触发 task。若 task 还有真实上游，它仍等待真实上游完成；若没有真实上游，它按现有根节点规则启动。`task -> end` 不会延迟 workflow 完成。

始末节点不参与角色解析、任务派发、格式检查、上游输出上下文、运行输出或状态事件。未来加入处理逻辑时，应从执行图构建的边界节点分支扩展，不需要迁移节点和边数据。

运行详情继续使用 workflow 定义中的完整节点和边展示画布。由于 node run 列表不含始末节点，前端将其显示为无运行状态的只读边界节点。

## 预检与错误处理

始末节点均为可选。缺少开始或结束节点不产生预检问题，也不阻止启用 workflow。

存在始末节点时执行以下预检：

- 开始节点没有出边：阻塞错误。
- 结束节点没有入边：阻塞错误。
- 开始节点存在入边：阻塞错误。
- 结束节点存在出边：阻塞错误。
- 开始节点直接连接结束节点：阻塞错误。
- 始末节点未分配阶段：沿用现有非阻塞警告。

始末节点跳过 worker、critic、role、split 等执行配置检查。它们及其边仍参与 DAG 循环检查，但不再产生普通孤立节点提示，避免与边界专用检查重复。

创建重复始末节点返回 `409 Conflict`。创建非法边或试图通过更新接口改变节点边界类型返回 `422 Unprocessable Entity`。前端保留当前画布状态并显示本地化错误提示。

## 组件与职责

- 共享节点格式模块：解析边界类型，提供无框架依赖的类型判定。
- 前端节点目录：暴露开始和结束模板，并根据现有节点控制可添加状态。
- 边界节点组件：负责编辑器、模板预览和运行详情中的统一视觉。
- 节点配置面板：根据边界类型切换为受限字段集合。
- 前端画布模型：将持久化边界节点转换为专用 React Flow 节点，并隔离普通节点交互。
- Workflow 写服务：校验边界节点唯一性、不可变类型和边方向。
- Workflow 运行服务：构建只包含真实节点和真实边的执行图。
- 预检模块：报告边界节点连接完整性和方向错误。

## 测试策略

只运行相关模块测试，不执行全量测试。覆盖：

- TypeScript 节点类型解析和边界判定。
- 节点选择器的始末节点条目、唯一性禁用和创建参数。
- 专用节点的 handle、只读状态和稳定尺寸。
- 边界节点受限编辑面板及字段保存。
- 编辑器、模板预览和运行详情的边界节点展示。
- 前端连线限制和本地化错误提示。
- 预检的可选节点、连接完整性、方向、阶段及执行配置跳过规则。
- Go 节点唯一性、类型不可变和边方向校验。
- 模板克隆保留始末节点及连接。
- 启动运行时不创建边界 node run。
- start 边不改变真实根节点判定，end 边不改变运行完成判定。
- 真实节点之间的依赖等待保持原有行为。

## 成功标准

- 用户可在 workflow 中分别添加、编辑、移动、连接和删除唯一的开始与结束节点。
- 始末节点在编辑器、模板预览和运行详情中一致显示。
- 非法节点或边无法通过前端或 API 写入。
- 不添加始末节点的既有 workflow 行为完全不变。
- 添加始末节点后，真实任务的创建、依赖、派发、输出和完成结果与不添加时一致。
- 代码中存在集中、可扩展的边界节点类型和运行分支，后续可加入实际处理逻辑。
