# 动态任务拆分 E2E 测试方案

> 基于 `docs/superpowers/specs/2026-07-12-dynamic-task-splitting-design.md`

## 一、Workflow 模板编辑

### 1.1 创建含 Split 节点的父模板
父模板包含至少 4 个环节：需求分析 → 任务拆分 → 编码 → 测试。任务拆分节点需配置：子模板、模式（barrier/pipeline）、max_concurrency、barrier 模式下的 max_failures。子模板为不含拆分节点的普通 workflow（如"编码实现 → 自测"）。

**验证点**：父模板保存成功，子模板可被 Split 节点选中。

### 1.2 编辑已有父模板
可修改 Split 节点配置（切换模式、调整并发数、更换子模板）并保存。

### 1.3 预检阻断
- 子模板含 kind=split 节点 → 拒绝保存，提示不允许嵌套拆分
- Split 节点未配置子模板 → 拒绝保存
- 子模板状态非 active → 提示不可用

## 二、完整主流程

### 2.1 Barrier 模式
父模板分配给 issue → 需求分析完成 → 任务拆分节点激活 → Agent 生成拆分方案 → 人审核通过 → 子 issue 批量创建，各自按子模板启动子 workflow → 所有子任务完成 → 父流程继续编码、测试环节。

### 2.2 Pipeline 模式
同上，但子 issue 全部创建后父任务拆分节点立即完成、下游编码和测试环节立即激活，不等待子任务执行结果。

## 三、审核交互

### 3.1 拆分方案审核
Agent 生成方案后，人可在审核面板中：查看子任务列表及依赖关系、修改标题/描述/负责人、新增子任务、删除子任务、仅勾选部分通过、调整依赖边。

**约束**：确认创建后仅勾选的子任务生成 issue，未勾选的被丢弃。

### 3.2 依赖合法性
- 构造循环依赖（A→B→C→A），审核提交被拒绝并提示环路
- depends_on 引用不存在的子任务，审核提交被拒绝

## 四、DAG 调度

### 4.1 拓扑顺序启动
子任务 A（无依赖）、B（依赖 A）、C（无依赖）、D（依赖 B 和 C）。A 和 C 立即启动，B 等 A 完成后启动，D 等 B 和 C 都完成才启动。

### 4.2 max_concurrency 限流
配置 max_concurrency=2，5 个无依赖子任务。任意时刻同时运行 ≤2 个，前一个完成后才释放配额给下一个。

### 4.3 依赖失败级联
子任务 A 失败 → 依赖 A 的 created 后继任务标记为 skipped，不启动。

### 4.4 依赖取消级联
子任务 A 被取消 → 依赖 A 的 created 后继任务标记为 skipped。

## 五、进度展示

### 5.1 画布节点状态
任务拆分节点在不同阶段展示不同状态：Agent 处理中 → 待审核（含子任务数） → 聚合进度（"3 done · 1 failed · 2 running"） → 完成。

### 5.2 父 Issue 详情页
展开任务拆分进度面板：所有子任务及状态可见、可跳转到对应 issue、失败子任务可查看错误详情、运行中子任务展示实时进度。

### 5.3 子任务 DAG 可视化
审核面板中以迷你画布展示子任务节点及其依赖连线。

## 六、取消级联

### 6.1 父节点取消
任务拆分节点 split_active 状态下触发取消（需二次确认）：所有活跃子 workflow run 被取消、子 issue 和子 split_task 非终态行标记 cancelled、父 node_run 和父 WorkflowRun 正确判定终态。

### 6.2 单子任务取消
barrier 模式中取消一个无后继的子任务，仅该任务和直接依赖它的后继受影响，其余子任务继续执行。

## 七、错误与恢复

### 7.1 Agent 生成失败
Agent 生成拆分方案出错 → 任务拆分节点标记 failed → 人可手动重试 → Agent 重新生成。

### 7.2 子 issue 批量创建失败
审核通过后创建子 issue 过程中某条失败 → 事务整体回滚 → 节点保持待审核状态 → 人修复后可重试。

### 7.3 子 workflow 启动失败
某子任务的 workflow run 启动失败 → 该 split_task 标记 failed → barrier 模式计入失败数。

### 7.4 幂等性
重复激活不重复生成拆分方案；重复提交审核不重复创建子 issue；重复调度不重复启动子 workflow run。

## 八、嵌套防护

### 8.1 编辑器预检
子模板含 kind=split 节点 → 编辑器拒绝保存。

### 8.2 运行时校验
即使绕过编辑器，Split 节点激活时后端仍需校验子模板不含 split 节点，校验失败则激活失败。

## 九、Barrier 终态判定

### 9.1 全部成功
所有非 discarded 子任务 done → 父任务拆分节点 completed → 下游编码、测试环节激活。

### 9.2 失败数 ≤ max_failures
max_failures=1，1 个子任务失败其余成功 → 父节点仍 completed。

### 9.3 失败数 > max_failures
max_failures=0，任意 1 个子任务失败 → 父节点 failed。

### 9.4 含 skipped 子任务
有子任务因依赖失败被 skipped，其余完成 → skipped 不计入失败数 → 失败数未超则父节点 completed。

## 十、Pipeline 模式特殊行为

### 10.1 父节点即时释放
子 issue 创建成功后父任务拆分节点立即完成，下游编码、测试环节立即激活。

### 10.2 子任务独立失败
Pipeline 模式下子任务执行失败不影响已完成的父节点，失败信息通过父 issue 进度面板展示。

### 10.3 后台调度继续
父节点完成后，后台仍按 DAG + max_concurrency 持续调度启动剩余子 workflow。

## 十一、边界场景

### 11.1 Agent 生成 0 个子任务
Agent 返回空列表 → 任务拆分节点标记 failed。

### 11.2 用户丢弃全部子任务
审核通过时 approved_task_ids 为空 → 所有子任务标记 discarded → 节点行为需确认产品设计。

### 11.3 并发审核提交
两人同时对同一拆分方案提交审核 → 先到者成功，后到者因行锁冲突返回错误。
