# 工作流用户旅程

> 从《企业编程协作平台-用户旅程》中提取的工作流相关内容，按序号排列，描述场景和操作。

## 1. 创建工作流

### 场景

成员创建工作流，用来定义一段研发协作流程中的节点、执行者、评审者、交付物和 Agent 能力。

### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 成员 | 录入工作流元数据：标题、描述 |  |
| 2 | 成员 | 添加节点：<br>- 录入节点元数据：标题、描述<br>- 关联研发阶段：支持用户创建<br>- 配置执行者：人 / 智能体 / 小队 / 研发角色<br/>- 配置评审者：人 / 智能体 / 小队 / 研发角色<br>- 定义交付物：文档 / PR，以及交付要求 | - 新增研发阶段定义<br>- 内置若干研发角色定义，动态映射关联研发岗位<br>- 新增交付物定义，同时移除节点 JSON Schema |
| 3 | 成员 | 连线节点：<br>- 串行<br>- 并行<br>- 不支持回路 |  |
| 4 | 成员 | 创建智能体：<br>- 录入智能体元数据：名称、描述<br>- 选择插件：Plugin / Skill，支持用户跳转至知识中心进行编辑创建<br>- 设置可见性：公开 / 私有<br>- 选择运行时（可选）：不可用时，支持路由至其他运行时<br>- 选择模型（可选）：不可用时，支持路由至其他模型<br>- 配置指令（可选） | - 支持智能体关联知识中心的 Plugin / Skill |
| 5 | 成员 | 创建小队：<br>- 录入小队元数据：名称、描述<br>- 选择 Leader Agent：负责接收分配给小队的任务并协调团队<br>- 添加成员：智能体 / 团队成员 |  |

## 2. 编辑工作流

### 场景

成员对已有工作流进行调整，用来更新工作流元数据、节点配置、节点连线和智能体能力。

### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 成员 | 选择需要编辑的工作流 |  |
| 2 | 成员 | 编辑工作流元数据：标题、描述 |  |
| 3 | 成员 | 编辑节点：<br>- 调整节点元数据：标题、描述<br>- 调整研发阶段<br>- 调整执行者：人 / 智能体 / 小队 / 研发角色<br>- 调整评审者：人 / 智能体 / 小队 / 研发角色<br>- 调整交付物：文档 / PR，以及交付要求 | - 复用研发阶段定义<br>- 复用研发角色动态映射关联研发岗位<br>- 复用交付物定义 |
| 4 | 成员 | 编辑节点连线：<br>- 串行<br>- 并行<br>- 不支持回路 |  |
| 5 | 成员 | 编辑智能体：<br>- 修改智能体元数据：名称、描述<br>- 调整插件：Plugin / Skill，支持用户跳转至知识中心进行编辑创建<br>- 调整可见性：公开 / 私有<br>- 调整运行时（可选）：不可用时，支持路由至其他运行时<br>- 调整模型（可选）：不可用时，支持路由至其他模型<br>- 调整指令（可选） | - 复用智能体与知识中心 Plugin / Skill 关联能力 |
| 6 | 成员 | 编辑小队：<br>- 修改小队元数据：名称、描述<br>- 调整 Leader Agent<br>- 调整成员：智能体 / 团队成员 |  |

## 3. 查看工作流执行情况

### 场景

成员查看自己相关的 Issue 执行情况，并在 Issue 详情中查看工作流全览、节点详情、交付物和智能体执行会话。

### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 成员 | 查看 Issue 看板 | 仅展示用户 Issue，隐藏工作流节点 Issue |
| 2 | 成员 | 查看用户 Issue 详情：<br>- 标题、描述、状态、负责人、项目、优先级、始末时间 等<br>- 评论信息<br>- 工作流全局总览：<br>  a. 阶段信息：阶段名称<br>  b. 连线情况<br>  c. 节点信息：<br>      - 节点元数据：标题<br>      - 处理者：人 / 智能体（评审中状态：显示评审者，其他状态：显示执行者）<br>      - 运行状态：待规划 / 待办 / 进行中 / 审核中 / 已完成 / 已阻塞<br>      - 交付物情况：红绿灯提交状态<br>      - 执行信息：耗时情况<br>  d. 交互操作：如果处理者是智能体<br>      - 进入会话<br>      - 重试 | 支持工作流全局总览视图 |
| 3 | 成员 | 进入会话：<br>- 跳转至会话空间：携带运行时ID及会话 ID<br>- 查看会话：实时打印智能体会话过程<br>- 介入会话：直接对话进行介入<br>- 托管会话：介入结束后将会话控制权交还给智能体 | 支持会话跳转、实时查看、人工介入和托管交还 |
| 4 | 成员 | 查看节点 Issue 详情：<br>- 标题、描述、状态、负责人、项目、优先级、始末时间 等<br/>- 评论信息<br/>- 交付物信息 |  |

## 4. 工作流节点内交互

成员在工作流节点内查看或处理节点任务，根据节点中的执行者 / 评审者类型进入不同交互方式。

### 4.1. 执行者

#### 4.1.1. 人

##### 场景

执行者为人工成员时，成员进入节点处理具体任务并提交交付物。

##### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 成员 | 接收任务：<br>- 平台：查看邮箱<br>- 手机：企微通知<br>- CSC：状态栏通知 | - CSC 新增状态栏通知<br>- 支持企微通知 |
| 2 | 成员 | 处理任务：<br>- 手机：选择到 平台 或 CSC 处理任务<br>- 平台：<br>  - 转智能体处理：指定智能体和运行时<br>  - 人工处理：内置协作指令<br>    - 跳转至会话空间：携带任务 ID<br>    - 人工处理任务<br>- CSC：内置协作指令<br>  - 人工处理任务 | 内置协作指令<br>- 查看任务清单<br>- 查看任务详情<br>  - 完整工作流上下文<br>  - 节点任务详情<br>  - 查看交付物内容<br>- 处理任务：流转状态 |
| 3 | 成员 | 完成任务：<br>- 交付物自检<br>- 使用内置指令提交交付物 | 内置协作指令<br>- 提交交付物：流转状态 |

#### 4.1.2. 智能体

##### 场景

执行者为智能体时，系统按工作流节点和研发阶段驱动智能体执行任务；不同研发阶段存在不同的协作和异常处理场景。

##### 4.1.2.1. 任务正常执行

###### 场景

智能体按照节点配置和运行时策略正常执行任务，适用于需求分析、方案设计、任务拆解、测试生成、编码、验证等阶段的常规任务。

###### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 系统 | 下发任务：<br>- 将任务状态设置为进行中<br>- 按运行时策略将任务下发至目标运行时 |  |
| 2 | 系统 | 创建目录：<br>- 基于 Worktree 创建工作目录 |  |
| 3 | 系统 | 下载插件：<br>- 下载 Plugin / Skill：作用范围仅限当前工作目录 | 支持从知识中心加载 Plugin / Skill |
| 4 | 智能体 | 执行任务：<br>- 节点上下文<br>- 交付物要求<br>- 插件能力 |  |

##### 4.1.2.2. 任务失败

###### 场景

适用于测试生成、编码、验证等阶段。当智能体执行失败时，系统保留失败证据，并引导成员重试、介入或转人工处理。

###### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 系统 | 通知用户：同时将任务状态设置为已阻塞<br>- 平台：查看邮箱<br>- 手机：企微通知<br>- CSC：状态栏通知 |  |
| 2 | 成员 | 人工介入：<br>- 重试任务<br>- 介入会话<br>- 人工处理 |  |

##### 4.1.2.3. 任务纠偏

###### 场景

适用于智能体执行方向偏离预期时。成员通过会话修正目标、约束或执行方向，再将任务托管回智能体。

###### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 成员 | 进入会话：实时查看智能体输出过程 |  |
| 2 | 成员 | 介入会话：对话指出偏差，并补充约束或修改目标 |  |
| 3 | 成员 | 托管会话：将会话控制权交还给智能体继续执行 |  |

##### 4.1.2.4. 头脑风暴

###### 场景

适用于需求分析、方案设计阶段。当智能体需要成员补充判断、约束或决策时，任务进入阻塞，并通过会话完成一次人机协作。

###### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 系统 | 通知用户：<br>- 平台：查看邮箱<br>- 手机：企微通知<br>- CSC：状态栏通知 |  |
| 2 | 成员 | 头脑风暴：<br>- 进入会话<br>- 介入会话：完成头脑风暴问答 |  |
| 3 | 成员 | 托管会话：将会话控制权交还给智能体继续执行 |  |

##### 4.1.2.5. 任务分配

###### 场景

适用于任务拆解阶段。智能体完成任务拆解和动态分配后，系统通知成员确认任务情况，成员可对任务依赖、承接对象和任务详情作出必要调整。

###### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 智能体 | 拆解任务：<br>- 识别任务依赖：串行 / 并行<br>- 动态分配任务：人 / 智能体 / 小队<br>- 确认任务详情：关联代码仓库、关联材料、任务描述、交付物要求等 | 支持任务动态分配：<br>- 成员分配：岗位、责任田、用户画像<br>- 智能体：标题、描述<br>- 小队：标题、描述 |
| 2 | 系统 | 通知用户：<br>- 平台：查看邮箱<br>- 手机：企微通知<br>- CSC：状态栏通知 |  |
| 3 | 成员 | 确认任务情况，并作出必要调整 |  |

##### 4.1.2.6. 代码提交

###### 场景

适用于编码阶段。成员或智能体基于任务关联的代码仓库完成开发并提交 PR；工作流内所有开发节点完成后，由智能体汇总代码变更并完成代码整合。

###### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 成员 / 智能体 | 创建任务：关联对应的代码仓库 |  |
| 2 | 成员 / 智能体 | 代码开发：<br>- 拉取代码仓库<br>- 完成开发任务<br>- 提交代码变更<br>- 将对应 PR 链接作为交付物上传 |  |
| 3 | 智能体 | 代码整合：工作流所有编码节点完成后的汇总节点<br>- 创建整合专用分支<br>- 整合代码并解决冲突<br>- 记录冲突解决细节 | 支持代码整合节点 |
| 4 | 成员 | 检查代码整合情况 |  |

#### 4.1.3. 小队

##### 场景

执行者为小队时，Leader 智能体负责小队内任务动态分配，并协调人 / 智能体完成任务。

##### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | Leader 智能体 | 小队内任务分配：<br>- 成员分配：岗位、责任田、用户画像<br/>- 智能体：标题、描述 |  |
| 2 | 人 / 智能体 | 同 执行者：人 / 智能体 的流程 |  |

### 4.2. 评审者

#### 4.2.1. 人

##### 场景

评审者为人工成员时，成员查看节点交付物和执行信息，并给出评审结论。

##### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 成员 | 接收任务：<br>- 平台：查看邮箱<br>- 手机：企微通知<br>- CSC：状态栏通知 |  |
| 2 | 成员 | 检视交付物：<br>- 手机：选择到平台或 CSC 处理任务<br>- 平台：<br>&nbsp;&nbsp;- 转智能体处理：指定智能体和运行时<br>&nbsp;&nbsp;- 人工处理：审查交付物<br>- CSC：<br>&nbsp;&nbsp;- 获取交付物<br>  - 人工审查 |  |
| 3 | 成员 | 完成评审：<br>- 通过：附评审意见<br>- 驳回：附评审意见<br>&nbsp;&nbsp;- 节点执行者是人：通知用户，状态重置<br>&nbsp;&nbsp;- 节点执行者是智能体：状态重置，原有会话下附评审意见继续 | - 新增通过/驳回操作<br>- 内置协作指令<br>  - 通过评审<br>  - 驳回评审 |

#### 4.2.2. 智能体

##### 场景

评审者为智能体时，成员查看智能体评审过程，并在必要时重试或人工介入。

##### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | 智能体 | 接收任务：获取待评审任务、节点上下文和交付物 |  |
| 2 | 智能体 | 检视交付物：<br>- 读取交付物内容<br>- 获取任务上下文和交付物要求<br>- 自动评审 |  |
| 3 | 智能体 | 完成评审：<br>- 通过：附评审意见<br>- 驳回：附评审意见<br>&nbsp;&nbsp;- 节点执行者是人：通知用户，状态重置<br/>&nbsp;&nbsp;- 节点执行者是智能体：状态重置，原有会话下附评审意见继续 |  |

#### 4.2.3. 小队

##### 场景

评审者为小队时，Leader Agent 协调小队完成评审，成员查看评审过程并在必要时介入。

##### 操作

| 步骤 | 角色 | 操作 | 开发项 |
| --- | --- | --- | --- |
| 1 | Leader 智能体 | 小队内任务分配：<br>- 成员分配：岗位、责任田、用户画像<br/>- 智能体：标题、描述 |  |
| 2 | 人 / 智能体 | 同 评审者：人 / 智能体 的流程 |  |
