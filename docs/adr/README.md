# 架构决策记录(ADR)

本目录存放 Multica 的架构决策记录(Architecture Decision Records,ADR)——
一份份简短、不可变的文档,用于记录某项**重要架构或跨模块决策"为什么这么做"**,
而不仅仅是"改了什么"(代码本身就说明了"改了什么")。

## 什么时候需要写 ADR

当一项决策符合以下任一条件时,建议写 ADR:

- **难以回退** —— 涉及鉴权、身份、数据归属,或服务间的对外契约。
- **跨模块/跨服务** —— 影响不止一个包、服务或团队。
- **非显而易见** —— 未来的读者很可能会问"当时为什么不选显而易见的另一种做法?"

纯功能实现、只改一个文件的 bug 修复、保持行为不变的重构,通常**不需要** ADR,
写在 PR 描述里即可。

## 格式

每份 ADR 是一个独立的 Markdown 文件,命名为 `NNNN-kebab-case-标题.md`,
`NNNN` 为零填充的顺序编号。建议章节:

- **状态**:Proposed / Accepted / Superseded by NNNN / Deprecated。
- **背景**:问题是什么、有哪些相互冲突的约束、相关证据。
- **决策**:我们选择了什么方案,用一般现在时陈述。
- **影响**:正面、负面、中性的后果。
- **备选方案**:还考虑过哪些方案、为什么否决。

ADR 是**只追加**的历史记录。如果某项决策被推翻,**不要**修改旧的 ADR,
而是新写一份,并把旧的那份状态改为 **Superseded by NNNN**。
