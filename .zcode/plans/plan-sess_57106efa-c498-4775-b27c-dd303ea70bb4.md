## 迁移老项目 console/notifications → 通知渠道

把老项目 `/cloud/console/notifications`(通知渠道配置)完整移植到当前项目已存在的 `/{slug}/channels` 路由(现为占位符)。

### 架构方案(复用 Hub 代理 — 同一 cloud-store 后端)

老页面的后端 `/api/channels*` + `/api/auth/identities` + `/api/auth/bind/start` 实测都在 **cloud-store 后端**(网关 `https://zgsm.sangfor.com/cloud-api`),和 Hub items/distributions **同源同鉴权**。当前 hub 代理已转发 `/api/admin/notification-channels`,只需**把 `/api/channels*` 和 `/api/auth/*` 加进同一 hub 代理白名单 + 路由注册**,无需新写代理处理器。

用户已确认:**完整移植全部功能**(渠道列表/enable-disable/test/delete/企微Bot二维码绑定轮询/IDTrust身份门禁)+ **装 qrcode 库前端生成二维码**。

### 风险/开放点
- **IDTrust OAuth 跳转**:`startBind` 返回 `authUrl` 后 `window.location.href` 跳转到 IDTrust,回调回 `/console/identity`。当前项目无此回调页 —— 跳转会回到老项目域名或 404。迁移时回调 URL 改指向当前项目(或保留原样,用户从老系统完成绑定后返回)。实测当前用户未绑 idtrust,门禁会显示;绑定跳转链路需要实际 IDTrust 环境,本地可能无法完整走通,但 UI + API 调用会正确。
- **企微Bot 二维码内容**:`botQRCode` 由后端在 `config.botQRCode` 返回,需先有 enabled 的 wecom-bot channel 才有值;空列表时该区块不渲染。
- 所有改动在 `new-ui-demo` 工作树,暂不提交。
